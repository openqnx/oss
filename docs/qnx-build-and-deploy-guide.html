Step 0

Before you start

You need a Linux build machine and an installed QNX SDP 8.0 with a valid licence. Nothing from the SDP’s prebuilt package set and nothing from repo.oss.qnx.com is reused — every binary here is compiled from upstream source, which is the whole point of the exercise.

# QNX SDP 8.0, installed and licensed
source $QNX_SDP_ROOT/qnxsdp-env.sh
qcc -V                 # should list gcc_ntoaarch64le and gcc_ntox86_64

# Build-machine packages (Ubuntu/Debian names)
sudo apt install build-essential git curl pkg-config \
     autoconf automake libtool gettext bison flex nasm \
     python3 python3-pip ninja-build meson cmake
CMake 4 caveat. Many of these projects still declare cmake_minimum_required(VERSION < 3.5), which CMake 4 rejects outright. env.sh exports CMAKE_POLICY_VERSION_MINIMUM=3.5 into the environment — not just as a -D flag, because nested cmake -P script runs (OpenCV’s pkg-config generator, for one) never see command-line defines.

Step 1

The workspace

Everything lives in one directory, separate from the SDP, which stays untouched and read-only throughout.

qnx-oss-ports/
  env.sh              # source it to enter the build environment
  toolchain/          # CMake toolchain files + Meson cross files, per arch
  recipes/<pkg>/      # recipe.sh (+ patches/*.patch)
  scripts/qnxbuild    # the driver
  scripts/check-*     # five staging audits + the coverage report
  tests/              # one QNX test binary per package
  src/                # fetched upstream sources (shared across arches)
  build/<arch>/<pkg>/ # out-of-tree build dirs
  stage/<arch>/       # the install tree -- this is the deliverable
  logs/  dist/

What belongs in version control

Only what is written by hand: the recipes and their patches, the driver and audits, the toolchain files, the tests and the docs — 497 files. Everything else is regenerated from those, and amounts to about 30 GB.

# .gitignore
/src/            /build/          /stage/       /stage.prev-*/
/logs/           /dist/           /hosttools/   /tmp/
/tests/build/
/tests/ssh/      <- the private key for the lab targets. Never commit this.
Two gitignore rules that are easy to get backwards. A pattern has no trailing comment — it runs to the end of the line, spaces included — so /src/ # upstream checkouts matches nothing and the next git add starts ingesting 12 GB. And a pattern whose only slash is at the end matches at any depth: an unanchored src/ also swallows tests/src/, quietly dropping all 165 hand-written test sources. Anchor them with a leading slash, as above.

The target prefix is /usr/local. Staging mirrors it per architecture at stage/<arch>/usr/local, so a file that will live at /usr/local/lib/libfoo.so.1 on the target sits at stage/aarch64le/usr/local/lib/libfoo.so.1 on the host. Every baked-in path — pkg-config prefixes, GStreamer plugin dirs, gettext locale roots — is therefore already correct for the target.

Step 2

What env.sh sets up

source ./env.sh aarch64le (or x86_64) does six things. Each one exists because something broke without it.

1
Rebuilds PATH from a remembered base. Both this file and the SDP’s qnxsdp-env.sh prepend to PATH every time they are sourced, and the driver sources it twice per package. At 218 packages PATH passed the kernel’s 128 KB limit for one environment string and every exec failed with “Argument list too long” — including the dirname that computes the workspace root, which then silently became the current directory.
2
Sources the SDP environment and derives the per-arch triple: aarch64-unknown-nto-qnx8.0.0 or x86_64-pc-nto-qnx8.0.0, with QCC_TARGET=gcc_nto<arch>.
3
Points pkg-config at staging only. PKG_CONFIG_LIBDIR is set (not PKG_CONFIG_PATH, which only adds) and PKG_CONFIG_SYSROOT_DIR maps the recorded /usr/local onto the staging tree. Host .pc files can then never leak in.
4
Creates compatibility stub archives. QNX folds librt, libdl, libpthread, libcrypt, libutil, libresolv, libanl and libatomic into libc, but portable build systems emit -lrt -ldl -lpthread unconditionally. Empty .a files in the staging lib dir turn those flags into no-ops — far cheaper than patching 200 build systems. Not libregex: QNX ships a real one, and an empty stub would shadow it.
5
Builds the link sysroot (“linkroot”). The QNX gcc spec injects its own -rpath-link ${QNX_TARGET}/<arch>/... ahead of anything you pass, and ld takes the first match. For any soname the SDP also ships — libssl.so.3, libcrypto.so.3, libxml2.so.2, libzstd.so.1 — the SDP’s older copy won. That is how libcurl’s valid call to SSL_get0_group_name came out as an undefined reference: it was checked against the SDP’s OpenSSL, not the 3.5.1 we built. The fix is a shadow tree of symlinks with our libraries overwriting the SDP names, and QNX_TARGET pointed at it — ld expands that variable from the environment, so its own spec redirects to us without the SDP being touched.
6
Puts hosttools/bin on PATH and hosttools/share/aclocal on ACLOCAL_PATH, for the native generators built in the next step.

Step 3

Host tools: the generators a cross build must run

This is the single most common way a cross build fails. A package compiles a helper with the cross compiler and then executes it on the build machine to generate a source file. The helper is a QNX binary, so Linux refuses it — Could not open '/usr/lib/ldqnx-64.so.2'.

Step 5

The compile and link contract

Every package is built with the same flags, set centrally. If you are porting a package by hand rather than through the driver, this is the contract to reproduce.

CMake — toolchain/qnx-<arch>.cmake

set(CMAKE_SYSTEM_NAME QNX)
set(CMAKE_C_COMPILER   "${QNX_HOST}/usr/bin/qcc")
set(CMAKE_CXX_COMPILER "${QNX_HOST}/usr/bin/q++")
set(CMAKE_C_COMPILER_TARGET gcc_ntoaarch64le)

# Assemble with the cross-GCC driver, not qcc: qcc accepts -march but does
# not forward it to the assembler, so .S files needing an ISA extension fail.
set(CMAKE_ASM_COMPILER "${QNX_HOST}/usr/bin/aarch64-unknown-nto-qnx8.0.0-gcc")

# -isystem, not -I: with -I the staging headers outrank a project's own
# include dirs, and vendored copies (protobuf's abseil) get cross-wired.
set(CMAKE_C_FLAGS_INIT   "-isystem ${QNX_STAGE}${QNX_PREFIX}/include")
set(CMAKE_CXX_FLAGS_INIT "-std=gnu++17 -isystem ${QNX_STAGE}${QNX_PREFIX}/include")

# QNX splits libc: these are never implicit.
set(CMAKE_C_STANDARD_LIBRARIES_INIT "-lsocket -lm -leventfd -lepoll -lsignalfd -ltimerfd -lfsnotify")
set(CMAKE_EXE_LINKER_FLAGS_INIT "-L${QNX_STAGE}${QNX_PREFIX}/lib -Wl,-rpath-link,${QNX_STAGE}${QNX_PREFIX}/lib ...")
Why -std=gnu++17 and not -std=c++17. Strict-ANSI mode switches off QNX’s __EXT_POSIX1* / __EXT_QNX guards, and ::stat, ::fstat, ::getpid and ::isatty simply disappear. The GNU dialect keeps them. The standard goes in CMAKE_CXX_FLAGS itself because check_cxx_source_compiles often clears CMAKE_REQUIRED_FLAGS, and QNX’s libc++ hard-errors below C++11.

Autotools

CC="qcc -V$QCC_TARGET -D_QNX_SOURCE" \
CXX="q++ -V${QCC_TARGET}_cxx -D_QNX_SOURCE" \
CPP="$QNX_HOST/usr/bin/$QNX_TRIPLE-gcc -E" \
CPPFLAGS="-D_QNX_SOURCE -I$STAGE$PREFIX/include -I$QNX_TARGET/usr/include" \
CFLAGS="$CPPFLAGS"  CXXFLAGS="$CPPFLAGS" \
LDFLAGS="-L$STAGE$PREFIX/lib -Wl,-rpath-link,$STAGE$PREFIX/lib \
         -lsocket -lm -leventfd -lepoll -lsignalfd -ltimerfd -lfsnotify" \
"$S/configure" --host="$QNX_TRIPLE" --prefix=/usr/local
  • _QNX_SOURCE goes on CC/CXX, not only in CFLAGS. A configure script may overwrite CXXFLAGS outright (zimg sets it to -fvisibility=hidden and drops everything you passed). The compiler variable survives that.
  • CPPFLAGS matters as much as CFLAGS. Autoconf runs its header probes with CPPFLAGS only; leave it unset and configure records the SDP’s version of a library while compilation sees yours.
  • CPP must be the cross-GCC driver. Autoconf otherwise derives "$CC -E", and qcc mishandles some preprocess-only invocations — libgpg-error then builds its error tables into empty headers, silently.
  • Staging include dirs come before the SDP’s. The SDP ships its own zlib 1.2.13 and friends; the brief is to build against what this workspace produced.
One unbroken continuation. Every assignment above must stay on one backslash-continued command. A comment line in the middle ends the command, and the assignments before it become ordinary shell variables configure never sees. That bug silently cost the driver its CC, CPP and all three flag variables for every autotools package — and they still built, because --host makes autoconf find the cross compiler by itself. Which is exactly why it went unnoticed.

Meson

meson setup "$B" "$S" --cross-file toolchain/meson-<arch>.ini \
      --native-file toolchain/meson-native.ini \
      --prefix=/usr/local --buildtype=release --default-library=both

The native file tells Meson where build-machine dependencies live (hosttools/), separately from the cross file’s QNX staging tree.

--default-library=both is not always right. ThorVG defines TVG_STATIC when it builds a static library, and the shared object produced in the same pass then exported zero symbols. It links, it installs, and every consumer fails at run time. That recipe builds shared-only. scripts/check-devlinks now fails on any staged .so that exports nothing.

Step 6

Patching

Patches live in recipes/<pkg>/patches/*.patch, are applied with patch -p1 in filename order, and are applied on first fetch only. The do_patch hook runs afterwards and is the place for regeneration (autoreconf -fi) or edits easier to express as sed.

# Adding a patch to a package that has already been fetched:
cd src/<pkg> && git diff > ../../recipes/<pkg>/patches/0002-fix-thing.patch
rm -rf src/<pkg>                      # REQUIRED -- see the warning below
./scripts/qnxbuild -f <pkg>
The trap that cost two rebuilds. Dropping a new patch file into a recipe whose source is already in src/ does nothing at all — the fetch stage is skipped, so the patch is never applied, and the build succeeds with the bug still in it. Delete src/<pkg> first. And a plain qnxbuild <pkg> after that still reports “already built (skip)”; you need -f.

Step 7

Build everything

cd ~/oss
./scripts/qnxbuild -l                      # status of every recipe
./scripts/qnxbuild $(ls recipes)           # both arches, deps resolved recursively

./scripts/qnxbuild -a aarch64le vsomeip    # one arch
./scripts/qnxbuild -f gettext              # force a rebuild

Dependencies are built recursively and each package stamps itself at stage/<arch>/.stamp/<pkg>. A full from-scratch rebuild of all 220 packages for both architectures takes about 3 h 25 min on a 16-core machine. Logs land in logs/<pkg>.<arch>.log.

Order matters more than it looks. gettext must be built with --enable-nls. It was originally --disable-nls, which installed no libintl at all — and 56 staged libraries silently linked the SDP’s prebuilt libintl.so.1 instead. Everything worked; it was simply not our build. That is the class of failure these audits exist to catch.

Step 8

Audit the staging tree

Five independent checks. All five pass on both architectures; each was written after a real defect got past the previous ones.

./scripts/check-all            # every audit, both architectures, one verdict

Run them individually while you are working on one:

./scripts/check-undefined <arch>  # unresolved symbols in staged libraries
./scripts/check-devlinks          # missing lib<name>.so symlink, or a .so exporting nothing
./scripts/check-sdp-leak          # a staged binary that falls back to an SDP prebuilt
./scripts/check-dupes             # one library stem staged under two sonames
./scripts/check-artifacts         # non-QNX ELF, wrong arch, dangling link, build path in a .pc
./scripts/check-test-coverage <arch>   # a package no test exercises
Use the wrapper, and here is why. The audits do not share one convention. check-undefined and check-test-coverage take the architecture as an argument and default to aarch64le; the other four loop over both themselves. Run the five in a row and x86_64 is genuinely verified four times out of five — the run still looks clean. Piping each through tail to shorten the output compounds it, because a pipeline reports tail’s exit status, which is always 0. check-all calls each audit correctly, keeps every exit code, and prints one verdict at the end.

Step 9

Build and bundle the tests

One QNX binary per package — 165 of them. Each links against the staging tree exactly as a downstream application would, which proves the headers, libraries and link lines are usable; running them on a target proves the ports actually work.

./tests/build-tests.sh                 # both arches -> stage/<arch>/usr/local/bin/qnx-port-tests/
./tests/make-bundle.sh aarch64le       # self-contained tarball in dist/ (~220 MB)

The bundle carries the test binaries, their full library closure, and the runtime data some libraries read: the CPython stdlib, enchant providers, GStreamer plugins, xkb keymaps, fontconfig, terminfo and libthai’s dictionary.

Step 10

Worked example: enca, end to end

A small package that exhibits the single most instructive cross-compilation failure, so it is worth following completely.

1. Where it comes from

git clone --depth 1 -b 1.19 https://github.com/nijel/enca.git src/enca

2. What goes wrong

enca compiles a helper, tools/make_hash, and then runs it to generate encodings.h. Built for the target it is a QNX binary, and the build dies in the Linux binfmt handler:

sed -f encodings.sed tools/encodings.dat | ./make_hash >encodings.h
aarch64-binfmt-P: Could not open '/usr/lib/ldqnx-64.so.2': No such file or directory
make[2]: *** [Makefile:671: encodings.h] Error 255

3. The fix

The generated header is architecture-independent, so build the generator natively, let the cross build fail once, swap the helper, and resume. That is the whole recipe:

VERSION=1.19; GIT=https://github.com/nijel/enca.git; REF=1.19
BUILDSYS=autotools
CONF_ARGS_EXTRA=( --enable-shared --disable-static --disable-external )

do_patch() { cd "$SRCROOT" && autoreconf -fi; }

do_build() {
  cc -O1 -o "$B/make_hash_native" "$S/tools/make_hash.c" -lm   # native
  make -C "$B" -j"$(nproc)" || true                            # expected to fail here
  install -m 755 "$B/make_hash_native" "$B/tools/make_hash"    # swap in the native one
  make -C "$B" -j"$(nproc)"                                    # resume
}
Read your logs with this in mind. enca’s build log contains make: *** Error 2 on both architectures by design — the || true pass. It is the only package in the tree where a failure marker in the log is not a failure, which is precisely why a log scan alone is not a verification method. What confirms it: a 426-line generated encodings.h and 60 exported enca_* symbols in the staged library.

4. Build, audit, test

./scripts/qnxbuild enca

Part II

Putting it on a Raspberry Pi 5

Step 11

Pick a route

The reference target is a Raspberry Pi 5 running QNX 8.0.0 RaspberryPi5 aarch64le. Its filesystem layout decides the route:

ifs          on /        type ifs     # read-only boot image
/dev/hd0t178 on /usr     type qnx6    # writable, 9.9G (5.8G free)
/dev/hd0t179 on /data    type qnx6    # writable, 19G (15G free)
RouteNeeds rootUse when
A — system install to /usr/localyesthe normal choice; every path compiled into the binaries is already correct
B — portable bundle in $HOMEnono root, or several builds side by side; needs environment overrides
C — NFS, read-onlyyestarget too small to hold the tree (a default mkqnximage VM has a 146 MB disk)

Step 12

Route A — system install to /usr/local

The staging tree is the deliverable: stage/aarch64le/usr/local is a drop-in overlay for the target’s /usr/local.

# 1. On the build machine -- pack the tree (about 1.2 GB unstripped)
cd ~/oss
tar czf qnx-local-aarch64le.tar.gz -C stage/aarch64le/usr local

# 2. Copy it to the Pi (HOME is on /data, which has room)
scp qnx-local-aarch64le.tar.gz qnxuser@:

# 3. On the Pi -- unpack into /usr, which needs root
ssh qnxuser@
sudo tar xzf ~/qnx-local-aarch64le.tar.gz -C /usr
ls /usr/local/lib | wc -l
Trim it first if you want. The tree is unstripped and carries static archives, headers and .pc files that a runtime-only target does not need. find /usr/local -name '*.a' -delete and ntoaarch64-strip on the shared objects take it down substantially. Keep the headers if the Pi is also a development machine.

Step 13

Route B — portable bundle, no root

# On the build machine
./tests/make-bundle.sh aarch64le
./tests/deploy-and-run.sh aarch64le

That unpacks under $HOME on the target — deliberately not /tmp, which on a small QNX image is a RAM disk where a 220 MB copy closes the connection mid-transfer and looks like a network fault. The bundle is relocatable: nothing inside it assumes /usr/local, because bin/qnx-port-tests/run-on-target.sh sets every path from its own location.

Route C — NFS, for targets with no room

./tests/run-over-nfs.sh x86_64  root

The target mounts the build machine’s home directory read-only (fs-nfs3 -r) and runs everything in place; only /tmp is written. If the image also lacks QNX’s own split-libc shims the script carries them from the SDP alongside the bundle.

Step 14

The runtime environment

QNX has no ld.so.conf; /usr/local/lib is not searched by default. These are the variables that matter, and every one of them was added because something failed without it.

# ~/.profile on the target (Route A paths shown)
export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
export PATH=/usr/local/bin:$PATH

export XKB_CONFIG_ROOT=/usr/local/share/X11/xkb     # keymaps
export FONTCONFIG_PATH=/usr/local/etc/fonts         # font config
export TERMINFO=/usr/local/share/terminfo           # ncurses
export LIBTHAI_DICTDIR=/usr/local/share/libthai     # compiled-in path is wrong when relocated

# GStreamer: elements are loadable modules, and the registry must be writable
export GST_PLUGIN_PATH=/usr/local/lib/gstreamer-1.0
export GST_PLUGIN_SCANNER=/usr/local/libexec/gstreamer-1.0/gst-plugin-scanner
export GST_REGISTRY=/tmp/gst-registry.bin

# Wayland refuses an XDG_RUNTIME_DIR that is not a 0700 dir owned by you
export XDG_RUNTIME_DIR=/tmp/run.$(id -u)
mkdir -p "$XDG_RUNTIME_DIR" && chmod 700 "$XDG_RUNTIME_DIR"
Python needs more than PYTHONHOME. A CPython embedded with an isolated config ignores PYTHONHOME entirely. It then searches PATH, finds the system /system/bin/python3, and loads QNX’s stdlib and prebuilt _ssl, _ctypes and _sqlite3 — a test that looked like it was exercising our Python and was not. Set PyConfig.home in the embedding code and assert the module paths.
