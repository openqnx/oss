Working guide · QNX SDP 8.0 · aarch64le + x86_64

Porting an open source package to QNX SDP 8.0

The procedure used for 218 packages in this workspace, with the commands to copy. Every fix below came from a build that actually failed — the symptom table is the fastest route from an error message to the thing that causes it.

Step 01Enter the environment

One script sets the compiler, the staging prefix, pkg-config, the native tool path and the link sysroot. Everything else assumes it has been sourced.

shell
cd ~/oss
source env.sh aarch64le      # or: source env.sh x86_64

# what you now have:
#   $QNX_TARGET   -> stage/<arch>/linkroot   (shadow tree, see the note)
#   $QNX_TARGET_SDP -> $QNX_SDP_ROOT/target/qnx  (the real SDP)
#   $STAGE$PREFIX -> stage/<arch>/usr/local  (where ports install)
#   CC = qcc -Vgcc_nto<arch> -D_QNX_SOURCE
Why QNX_TARGET points at a shadow tree. The QNX gcc spec injects its own -rpath-link with four SDP directories ahead of anything you pass, and ld takes the first match — so a transitive DT_NEEDED for a soname the SDP also ships (libssl.so.3, libxml2.so.2, libzstd.so.1…) resolves to the SDP's older copy. ld expands that literal ${QNX_TARGET} from the environment, so env.sh builds stage/<arch>/linkroot — every SDP entry symlinked through, with <arch>/usr/lib a real directory where our libraries overwrite the SDP's names — and points QNX_TARGET at it. The SDP itself is never modified.

Step 02Write the recipe

A recipe is a shell fragment at recipes/<name>/recipe.sh. Declare where the source comes from, which build system it uses, and what it depends on. The driver does the rest.

CMake — the default, no BUILDSYS line needed

recipes/zstd/recipe.sh
VERSION=1.5.6; GIT=https://github.com/facebook/zstd.git; REF=v1.5.6
SUBDIR=build/cmake                # CMakeLists.txt is not at the root
CMAKE_ARGS_EXTRA=( -DZSTD_BUILD_SHARED=ON -DZSTD_BUILD_PROGRAMS=OFF
                   -DZSTD_BUILD_TESTS=OFF
                   -DCMAKE_POSITION_INDEPENDENT_CODE=ON )

Meson

recipes/pixman/recipe.sh
VERSION=0.44.2; GIT=https://gitlab.freedesktop.org/pixman/pixman.git
REF=pixman-0.44.2
DEPS="libpng"                  # built first, automatically
BUILDSYS=meson
MESON_ARGS_EXTRA=( -Dtests=disabled -Ddemos=disabled
                   -Dgtk=disabled -Dlibpng=enabled )

autotools

recipes/libexif/recipe.sh
VERSION=0.6.24; GIT=https://github.com/libexif/libexif.git; REF=v0.6.24
BUILDSYS=autotools
CONF_ARGS_EXTRA=( --enable-shared --disable-static --disable-docs --disable-nls )

# Cache variables for probes configure cannot run across a cross build:
# CONF_ENV=( ac_cv_file__dev_ptmx=yes ac_cv_header_sys_termio_h=no )

# Regenerate the build system when the tree ships no ./configure:
# do_patch() { cd "$SRCROOT" && autoreconf -fi; }

Tarball instead of git, and custom builds

recipes/<name>/recipe.sh — other forms
# A release tarball (use when the repo needs credentials or has no tags)
VERSION=0.5
TARBALL=https://xorg.freedesktop.org/releases/individual/lib/libpthread-stubs-0.5.tar.xz

# A project with no build system at all: override the hooks.
# $S = source dir, $B = build dir, both already set.
BUILDSYS=custom
do_build() {
  "$QNX_HOST/usr/bin/qcc" -V"$QCC_TARGET" -O2 -fPIC -D_QNX_SOURCE \
    -I"$S/src" -c "$S/src/duktape.c" -o "$B/duktape.o"
  "$QNX_HOST/usr/bin/qcc" -V"$QCC_TARGET" -shared \
    -Wl,-soname,libduktape.so.207 -o "$B/libduktape.so.207.0.0" \
    "$B/duktape.o" -lm
}
do_install() {
  install -d "$STAGE$PREFIX/lib" "$STAGE$PREFIX/include"
  install -m 755 "$B/libduktape.so.207.0.0" "$STAGE$PREFIX/lib/"
  ln -sfn libduktape.so.207.0.0 "$STAGE$PREFIX/lib/libduktape.so.207"
  ln -sfn libduktape.so.207     "$STAGE$PREFIX/lib/libduktape.so"
  install -m 644 "$S/src/duktape.h" "$STAGE$PREFIX/include/"
}
Declare every dependency in DEPS, even one you know is already built. An undeclared dependency does not fail loudly — it makes the build depend on the order packages happen to be listed in. Worse, it can link the SDP's prebuilt copy instead: gettext linked the SDP's ncurses for exactly this reason, and that only surfaced in a from-scratch rebuild.

Step 03Build and read the log

shell
./scripts/qnxbuild -l                    # status of every recipe
./scripts/qnxbuild mypkg                 # both architectures
./scripts/qnxbuild -a aarch64le mypkg    # one architecture
./scripts/qnxbuild -f -a aarch64le mypkg # force rebuild (ignores the stamp)

# The log is the whole story; the console only prints headlines.
grep -nE "error:|undefined reference|No such file" logs/mypkg.aarch64le.log | head
Patches apply on first fetch only. After editing a patch, delete the source tree so the driver re-clones and re-applies: rm -rf src/mypkg && ./scripts/qnxbuild -a aarch64le mypkg. Editing src/ directly is fine while iterating — just make sure the change ends up in recipes/ before you finish (step 05).

Step 04Fix what QNX breaks

Roughly a quarter of packages need a source change. Decide which kind of change it is before writing it — the right fix is usually smaller than it first looks.

build flag

A feature detected that QNX cannot support. Disable it in the recipe with a cache variable or a -D, and say why in a comment. No patch needed.

platform list

The most common real patch. A #if defined(__linux__) or a configure case $host_os that simply predates QNX. Add QNX beside the platform it behaves like, don't invent a new branch.

missing API

QNX has an equivalent under another name or header — posix_madvise for madvise, <unix.h> for openpty. Check the semantics, not just the name: posix_madvise returns the error instead of setting errno.

absent concept

No equivalent exists (EPOLLET, SA_RESTART). Prefer failing honestly over pretending: guard the constant so a caller gets an error, rather than defining it to 0 and silently changing behaviour — unless 0 genuinely is a no-op.

An existing QNX branch is not evidence that QNX works. Most upstream QNX support targets 6.x or 7.x and actively breaks on 8.0. x264's *qnx* case put a Visual C++ header on the include path; vsomeip carried an accept4 emulation QNX 8 no longer needs; CPython's LINKCC=qcc case was written for native builds and dropped the cross target selector. Always check what the branch was written against.

Symptom → fix

Every row here is a build that failed in this workspace. Search for your error text.

ErrorCause and fix
undefined reference to 'eventfd'
…'epoll_create1', 'signalfd', 'timerfd_create'		 QNX splits libc: these live in libeventfd, libepoll, libsignalfd, libtimerfd. The toolchain files already link them; if the package links with raw ld, add them to its LDFLAGS.
undefined reference to 'regcomp' QNX has a real libregex.so in $QNX_TARGET/<arch>/lib. Add -lregex. Do not add a compat stub — that shadows the real library.
cannot find -lrt / -ldl / -lpthread Folded into libc on QNX. env.sh stages empty stub archives so these flags become no-ops; nothing to do.
'SA_RESTART' undeclared QNX leaves it commented out ("not supported yet") — kernel calls return EINTR. #define SA_RESTART 0 under a __QNX__ guard is a true no-op.
'EPOLLET' undeclared
'EPOLLRDHUP' undeclared		 QNX's epoll is level-triggered only. Either disable the epoll backend, or define the bit to 0 and stop advertising the capability so callers can pick another path.
'posix_memalign' was not declared It is in <malloc.h>, not <stdlib.h>, and gated behind __EXT_POSIX1_200112 — so -std=c++14 hides it. Include the header and keep -D_QNX_SOURCE.
::stat / ::getpid has not been declared -std=c++17 defines __STRICT_ANSI__, which switches off QNX's __EXT_* declarations. The toolchain sets -D_QNX_SOURCE globally; for autotools put it on CC/CXX, not just CFLAGS — configure may overwrite the flag variables.
#error termio/termios incompatibility QNX's <sys/termio.h> and <termios.h> are mutually exclusive. Tell configure the first is absent: ac_cv_header_sys_termio_h=no.
<sys/syscall.h>: No such file
<sys/sysinfo.h> / <pty.h> / <linux/input.h>		 Microkernel — no syscall table. Use the library function instead. openpty/forkpty are in <unix.h>; sysinfo becomes sysconf.
cross build not supported for …-nto-qnx
could not identify NASM format for nto-qnx		 A platform table with no QNX entry. Add QNX beside the closest match — Linux for ELF/NASM, VxWorks for RTOS cases.
Relocations in generic ELF (EM: 183) The wrong architecture's linker. Bare qcc uses its default target; the driver must carry -V<target>. Look for a hard-coded LINKCC=qcc or similar.
relocation R_AARCH64_ADR_PREL_PG_HI21 …
can not be used when making a shared object		 Objects compiled without -fPIC, usually because a per-platform CCSHARED-style variable has no QNX entry.
operand mismatch — `mov v0.8h,v4.8h'
invalid addressing mode — `ld1 {v4.16b},[x3,80]'		 Clang-isms in hand-written NEON that the SDP's GNU as rejects. Use .16b for register moves; change "m" asm operands to "r" with an explicit [%N].
__multc3 … final link failed: bad value
every meson probe fails		 QNX's libm.so references a symbol hidden in static libgcc. Add -shared-libgcc — already in the meson cross files.
Could not load library at run time
…naming a file that is present		 A dangling link in a multi-level symlink chain (libfoo.so → .so.6 → .so.6.5). Copy every step, not just the head and the resolved file.
cannot run test program while cross compiling A run-time probe. Supply the answer as a cache variable — and look it up rather than guessing. QNX documents malloc(0): "returns a valid pointer with a size of zero".
is not a valid libtool archive .la files record absolute target paths. The driver deletes them from staging after every install, as Yocto and Buildroot do.
An exe_wrapper is needed but was not found
must install xdt-csource		 The source is a git checkout. GTK4 compiles its CSS from Sass and Xfce regenerates *-aliasdef.c only for git trees, and both need to run a tool. Use the project's release tarball (TARBALL=), which ships the generated files.
sys/shm.h: No such file or directory QNX 8.0 has no System V shared memory — no shmget/shmat, only shm_open. X11's MIT-SHM therefore cannot exist. Take the package's no-SHM path (cairo has one; see recipes/cairo/patches) or disable the backend.
sys/asoundlib.h: No such file That is QSA, the QNX 6.x/7.x sound API. QNX 8.0 ships a real alsa-lib (<alsa/asoundlib.h>). Gate the QSA backend off and let the package's generic ALSA check pick up (SDL2, SDL3).
no type named 'type' in 'enable_if<false, int>' (from from_chars_integral.h) QNX 8.0's libc++ has std::from_chars for integers only. Use strtod on a NUL-terminated copy, and reject what chars_format::general would reject (+, hex, inf/nan) to keep the semantics.
'W_EXITCODE' was not declared A glibc/BSD convenience macro. QNX's wait-status encoding is the same (WEXITSTATUS is (s>>8)&0xff), so #define W_EXITCODE(r,s) ((r)<<8|(s)) under #ifndef.
cc: unknown option: '--include' qcc parses its own options first and rejects GCC's long spellings. Replace --include with -include (in Makefile.am and Makefile.in for a tarball).
Inappropriate I/O control operation at run time The request is defined in QNX's headers but not implemented by the resource manager — TIOCPKT on devc-pty, for one. Turn the feature off at compile time, and turn off every site that depends on it together: VTE's reader strips a packet byte that would no longer be there.
Could NOT find PkgConfig (missing: PKG_CONFIG_EXECUTABLE) CMake found a target pkgconf under the staging prefix, could not run it, and said nothing more. The toolchain files now put stage/…/bin in CMAKE_IGNORE_PATH; check that yours do.
ld: warning: libX.so.N, needed by …, may conflict with libX.so.M The same library is staged twice, usually because a package installed a vendored copy. This is how gRPC put a second protobuf and abseil beside ours. Switch the package to its PROVIDER=package/system option and run scripts/check-dupes.
undefined reference to 'lua_pcallk' linking against LuaJIT Compiled against Lua 5.4's lua.h, which lives in the same prefix. An imported CMake target's include dir is passed as -isystem, after the toolchain's; add it as a plain -I (target_include_directories(… BEFORE PRIVATE …)).
Crash on the first line of any script, in generated-VM code (LuaJIT) A build-machine generator compiled for a different target OS than the target code. LuaJIT's buildvm used LUAJIT_OS_OTHER; the target used POSIX; the struct layouts differ by 16 bytes. Make the generator see the same configuration (recipes/luajit/files).
Could not load library libeventfd.so.1 on every test The target image omits QNX's split-libc libraries (a default mkqnximage build does). Use a fuller image, or tests/deploy-and-run-chunked.sh … --with-os-runtime to carry them from the SDP.
scp: Connection closed / tar: No space left on device while deploying The target is out of disk, not off the network — a default image has 147 MB in total. Use tests/deploy-and-run-chunked.sh, which streams one batch at a time.

Step 05Record the patch

A fix that lives only in src/ is lost on the next clean build. Patches go in recipes/<name>/patches/ and are applied in filename order on first fetch.

shell
# git checkout: diff against HEAD
mkdir -p recipes/mypkg/patches
git -C src/mypkg diff > recipes/mypkg/patches/0001-qnx-short-description.patch

# tarball: diff against a pristine extract of the same release
mkdir -p /tmp/orig && tar xf dist/mypkg-1.2.3.tar.gz -C /tmp/orig \
  --strip-components=1 mypkg-1.2.3/src/thing.c
diff -u /tmp/orig/src/thing.c src/mypkg/src/thing.c \
  | sed '1s|.*|--- a/src/thing.c|; 2s|.*|+++ b/src/thing.c|' \
  > recipes/mypkg/patches/0001-qnx-short-description.patch

# verify it applies to a pristine tree
rm -rf src/mypkg && ./scripts/qnxbuild -a aarch64le mypkg
Write the patch as if you were sending it upstream. Comment why QNX differs, not just what changed — the comment is what stops the next person re-deriving it. Patches that only a cross build needs (a cache variable, a -D) belong in the recipe, not in a patch.

Step 06Write a real test

Linking proves headers and libraries are usable. It proves nothing about behaviour. Exercise the library's actual API and check results against known values.

tests/src/test_mypkg.c
/* One line per check; exits 0 only if every check passed. */
#include "common.h"
#include <mypkg.h>

int main(void) {
  QT_BEGIN("mypkg");
  printf("  info version %s\n", mypkg_version());

  /* Round-trip, not just "did it return non-NULL". */
  char out[64];
  QT_CHECK(mypkg_encode("qnx", out, sizeof out) == 3, "encode");
  QT_CHECK(strcmp(mypkg_decode(out), "qnx") == 0, "round trip");

  /* A published test vector beats a self-consistent one. */
  QT_CHECK(mypkg_hash("abc") == 0x352441c2, "reference vector");

  /* The error path matters as much as the happy path. */
  QT_CHECK(mypkg_decode("not valid") == NULL, "bad input is rejected");
  QT_END();
}
tests/CMakeLists.txt
# plain library name
port_test(test_mypkg   test_mypkg.c   mypkg)

# headers under a subdirectory
target_include_directories(test_mypkg PRIVATE "${INC}/mypkg-2")

# or let pkg-config supply the flags
pkg_check_modules(MYPKG REQUIRED IMPORTED_TARGET mypkg-2.0)
port_test(test_mypkg   test_mypkg.c   PkgConfig::MYPKG)
Honour the alignment and lifetime contracts the API documents. zimg requires 32-byte aligned buffers on x86. A plain malloc gives 16 — which aarch64's NEON accepts by accident, so the test passed there and segfaulted only on x86_64. Test both architectures before believing a result.

Step 07Run it on hardware

Cross-built binaries cannot run on the build host. The bundle carries the test binaries plus only the libraries they pull in — and the run-time data some of them read from disk.

shell
./tests/build-tests.sh          # both arches
./tests/make-bundle.sh          # dist/qnx-port-tests-<arch>.tar.gz

./tests/deploy-and-run.sh aarch64le <target>   # copy, unpack under $HOME, run

# a target too small for the whole bundle (default mkqnximage: 147 MB disk):
./tests/deploy-and-run-chunked.sh x86_64 <target> 12
#   ...and if the image lacks QNX's own libeventfd/libsocket/...:
./tests/deploy-and-run-chunked.sh x86_64 <target> 12 --with-os-runtime
Loadable modules and data files are invisible to a DT_NEEDED walk. GStreamer elements and gdk-pixbuf loaders are dlopened, so a dependency walk packages none of them — the registry then comes up with one plugin and every gst_element_factory_make() returns NULL. The bundler carries the plugin directory, gst-plugin-scanner, enchant's provider modules, the XKB rules, fontconfig's config, the terminfo database and libthai's dictionary; the runner exports the matching environment variables. The chunked runner reuses run-on-target.sh rather than re-creating that environment — re-creating it is how Wayland and GStreamer tests came back "failing" when they were fine.
Relocatable libraries need to find themselves. gnulib's relocate() locates a shared library through /proc/self/maps, which QNX lacks, so on QNX it silently returns every path unchanged. enchant then looked for its plugins at the configure-time prefix and found none. dladdr() works on QNX; see recipes/enchant/patches.

To debug a crash on target, gdb is already there — but note it resolves symbols from the target's own /usr/lib, which may shadow the library you shipped:

on the target
LD_LIBRARY_PATH=$PWD/lib gdb -batch -ex run -ex bt ./bin/test_mypkg

Step 08Audit the staging tree

Four checks catch the failures that do not announce themselves. Run them after every batch, not at the end.

shell
./scripts/check-undefined     # holes in shared libraries
./scripts/check-devlinks      # missing lib<name>.so symlinks
./scripts/check-sdp-leak      # binaries loading an SDP prebuilt library
./scripts/check-dupes         # one library staged under two sonames
check-undefined

Shared libraries link with undefined symbols allowed, so a forgotten target_link_libraries installs cleanly and fails only when an executable finally links it. This is how libyuv's missing libjpeg and SVT-AV1's missing cpuinfo_isa were found.

check-devlinks

A library staged as libfoo.so.8 with no libfoo.so is not a link error — -lfoo keeps searching and finds the SDP's prebuilt copy. Silent downgrade. It also flags a shared library that exports no symbols at all, which is what ThorVG built when --default-library=both defined its static-build macro.

check-sdp-leak

Reports any staged binary whose DT_NEEDED names a soname we do not provide but do build — i.e. it loads QNX's prebuilt library on target. This is the check that actually enforces "build everything from source".

check-dupes

Reports a library stem staged under more than one soname. Packages that vendor their dependencies install them: gRPC put protobuf 29.0 and 86 abseil libraries beside the ones already staged, and a gRPC process mapped both. It cannot see a same-soname overwrite (gRPC also replaced c-ares's libcares.pc); a package's install manifest can.

Finish with a from-scratch rebuild. Move stage, build, src and dist aside, then ./scripts/qnxbuild $(ls recipes) — the driver keeps going past a failure, so one run lists every problem. An incremental tree hides ordering assumptions: it is how three undeclared dependencies and a driver bug that made glib stamp itself "built" while installing nothing all went unnoticed. Every earlier build had worked by luck of ordering.

Native helper tools

Some tools must run on the build machine. A cross-built copy is a QNX binary and cannot. scripts/build-host-tools.sh builds these into hosttools/.

gettext

xgettext/msgfmt run during almost every GNOME build.

nasm

x86_64 assembly in dav1d, openh264, libvpx, FFmpeg, libass. Without it those builds fail or silently fall back to C.

wayland-scanner

Turns Wayland's XML protocol definitions into C.

trietool

libthai generates its word-break dictionary by running it. Taking the --disable-dict escape ships a libthai that cannot break Thai text.

xorg-macros

Every X.Org configure.ac opens with XORG_MACROS_VERSION; autoreconf refuses without it. ACLOCAL_PATH must point at it.

python3.14

Cross-building CPython needs a native interpreter of the same version — the build freezes its own stdlib with it and --with-build-python rejects a mismatch.

Rules worth internalising

  • A clean build is not a working port. Every serious defect found here compiled and linked without complaint.
  • Test both architectures. Orc's missing JIT target appeared only on aarch64; SVT-AV1's unresolved symbol and zimg's alignment crash only on x86_64.
  • Look the answer up. QNX documents malloc(0), its feature-test macros and which library holds which symbol. Guessing produces a flag that makes configure proceed and a behaviour change you will not notice.
  • Prefer an honest failure to a silent downgrade. Leaving select.EPOLLET undefined gives an AttributeError; defining it to 0 gives level-triggered semantics to code that asked for edge-triggered.
  • Read what the SDP already ships. QNX's own python3.13/pyconfig.h settled which CPython features are genuinely unavailable — useful as a reference even though its binaries are not reused.
  • A defined macro is not an implemented feature. TIOCPKT is in QNX's headers and not in its pty driver. Compile-time probes answer "does the name exist", not "will the kernel do it".
  • Use one copy of everything. Vendored dependencies turn into duplicate libraries the moment a package installs them. Prefer the package's option to use what is already built.
  • Generators must see the target the compiler sees. A tool compiled for the build machine that emits target code or offsets has to be configured as the target, or the layouts disagree silently.
  • Comment the why. Every workaround here carries the failure it prevents. That is what stops the next person deleting it.
