Package: gperf-3.1-r0.apk. Setting up apk: INSTALL.md 2A.

B-1. oss-get

No apk: target/oss-get downloads, checks the SHA-256, installs the dependencies first and keeps a file list per package:

oss-get update
oss-get install gperf
oss-get install gperf=3.1-r0   # this version

oss-get remove gperf   # its files only

nothing

Install: download, check, save the file list, unpack under /data/oss:

mkdir -p /data/oss/dl /data/oss/var/lib/manual && cd /data/oss/dl
curl -fsSLO https://github.com/openqnx/oss/releases/download/packages-8.0-x86_64/gperf-3.1-r0.tar.gz
[ "$(openssl dgst -sha256 gperf-3.1-r0.tar.gz | sed 's/.*= *//')" = e8e737d418b4f2e86f7f3ca1f9f3de60f75d204ebb5e879216c7121e2cc9ab67 ] && echo OK || echo BAD
gzip -dc gperf-3.1-r0.tar.gz | tar -tf - | grep -v '/$' > /data/oss/var/lib/manual/gperf.list
gzip -dc gperf-3.1-r0.tar.gz | (cd /data/oss && tar -xf -) && rm gperf-3.1-r0.tar.gz

Remove: delete exactly the files it installed, then the list:

cd /data/oss && while read -r f; do rm -f "$f"; done < var/lib/manual/gperf.list
rm var/lib/manual/gperf.list

For a root shell on the target (QNX sh and the stock curl, openssl, gzip, tar; https needs SSL_CERT_FILE, see INSTALL.md). Empty directories stay. Don't remove a dependency another installed package still needs. Use one method per /data/oss: apk and oss-get do not know about files unpacked by hand.
