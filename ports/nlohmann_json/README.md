## Install the prebuilt package on a target

No build needed: [`oss-get`](../../target/oss-get) downloads the package (and its run-time dependencies), checks its SHA-256 and unpacks it.

```sh
# on the QNX target
oss-get update
oss-get install nlohmann_json
oss-get install nlohmann_json-dev    # only for building on the target: headers, .pc, CMake files
```

See [docs/packages.md](../../docs/packages.md) for setting up `oss-get` on a board.

## Build it from upstream

Every step below can be run by hand. `./scripts/qnxbuild nlohmann_json` performs exactly the same steps (2–5) in one command.

### 1. Build environment

A Linux host with QNX SDP 8.0 installed and licensed — or the container in [`docker/`](../../docs/build-environment.md), which needs only the SDP mounted. Then, from the repository root:

```bash
export QNX_SDP_ROOT=$HOME/qnx800      # your SDP 8.0 installation
./scripts/build-host-tools.sh          # once per machine
source ./env.sh aarch64le              # or x86_64; once per shell
```

`env.sh` sets up the cross compiler (`qcc`/`q++`), the staging tree `stage/<arch>/usr/local` (= `/usr/local` on the target), pkg-config, and the CMake/Meson toolchain files.

No other component has to be built first.

### 2. Get the upstream source

```bash
git clone --depth 1 -b v3.12.0 --recurse-submodules --shallow-submodules \
    https://github.com/nlohmann/json.git src/nlohmann_json
```

### 3. Apply the QNX patches

None — the upstream source builds for QNX unmodified; everything QNX-specific is in the configuration below and in the shared toolchain files.

### 4. Configure, build and install into the staging tree

```bash
cmake -S src/nlohmann_json -B build/$QNX_ARCH/nlohmann_json -G Ninja \
      -DCMAKE_TOOLCHAIN_FILE=$PWD/toolchain/qnx-$QNX_ARCH.cmake \
      -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr/local \
      -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DBUILD_TESTING=OFF \
      -DJSON_BuildTests=OFF \
      -DJSON_Install=ON
cmake --build build/$QNX_ARCH/nlohmann_json -j$(nproc)
DESTDIR=$STAGE cmake --install build/$QNX_ARCH/nlohmann_json
```

Or all of steps 2–4 at once: `./scripts/qnxbuild -a $QNX_ARCH nlohmann_json`.

### 5. What it installs

50 files under `/usr/local`, 46 headers.

The complete list is `stage/<arch>/.manifest/nlohmann_json` after a build.

### 6. Package it for the target

```bash
./scripts/qnxpkg -a $QNX_ARCH nlohmann_json
ls repo/8.0/*/ | grep '^nlohmann_json-'
```

This writes `nlohmann_json-<ver>-r0.tar.gz` (run time) and `nlohmann_json-dev-<ver>-r0.tar.gz` (headers, pkg-config, CMake files, static libraries), the matching `.apk` files, and updates the repository index. The run-time dependencies recorded in the package are computed from the binaries.

## Run it on a target

Either install from your own repository (serve `repo/8.0/` with any web server):

```sh
# on the target
export OSS_REPO=http://<build-host>:8000
oss-get update && oss-get install nlohmann_json
```

or copy the tarball and unpack it yourself:

```bash
scp repo/8.0/aarch64/nlohmann_json-*-r0.tar.gz root@<target>:/data/
ssh root@<target> 'cd /data/oss && tar xzf /data/nlohmann_json-*-r0.tar.gz'
```

QNX has no `ld.so.conf`; make the libraries findable with `export LD_LIBRARY_PATH=/usr/local/lib` (with `oss-get link`) or `eval $(oss-get env)`.

### Test

[`test_nlohmann_json`](../../tests/src/) links nlohmann_json the way an application would and checks its core API on the target:

```bash
./tests/build-tests.sh $QNX_ARCH
scp stage/$QNX_ARCH/usr/local/bin/qnx-port-tests/test_nlohmann_json root@<target>:/data/
ssh root@<target> 'LD_LIBRARY_PATH=/usr/local/lib /data/test_nlohmann_json'
```

```

```

`./tests/make-bundle.sh && ./tests/deploy-and-run.sh <arch> <target>` runs every test at once.
